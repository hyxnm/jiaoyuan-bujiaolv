# 群众路线闭环 — 好主意不在书房里

## R — 原文 (Reading)

> 「在我党的一切实际工作中，凡属正确的领导，必须是从群众中来，到群众中去。这就是说，将群众的意见（分散的无系统的意见）集中起来（经过研究，化为集中的系统的意见），又到群众中去作宣传解释，化为群众的意见，使群众坚持下去，见之于行动，并在群众行动中考验这些意见是否正确。然后再从群众中集中起来，再到群众中坚持下去。如此无限循环，一次比一次地更正确、更生动、更丰富。」

> 「任何有群众的地方，大致都有比较积极的、中间状态的和比较落后的三部分人。故领导者必须善于团结少数积极分子作为领导的骨干，并凭借这批骨干去提高中间分子，争取落后分子。」

> 「只有领导骨干的积极性，而无广大群众的积极性相结合，便将成为少数人的空忙。」

—— 毛泽东《关于领导方法的若干问题》

---

## I — 方法论骨架 (Interpretation)

**你想出来的好主意，多半不是好主意——至少在被验证之前不是。**

正确主张的来源和归宿是一个闭环：

```
分散意见 → 集中研究 → 系统主张 → 回到人群 → 化为他们的行动 → 在行动中检验 → 再集中
```

三个关键：

1. **"集中"不是汇总**。群众的意见是分散的、无系统的、互相矛盾的。集中的过程是**研究**——去粗取精，找出真正的共同需求，形成系统的主张。**这不是投票，是加工。**
2. **"到群众中去"不是通知**，是宣传解释，让他们理解、化为他们自己的意见，然后**在他们的行动结果里检验**。
3. **骨干和群众，缺一不可**。只有骨干积极，是少数人的空忙；只有群众积极没有骨干组织，热情既不持久也不走向正确方向。
   - **三部分人分档**：团结积极分子（10-20%）当骨干 → 用骨干提高中间分子（多数）→ 靠这两部分争取落后分子（投入产出比最低，控制投入）
   - **骨干要流动**：事情推进中会冒出新的积极分子，也会有原来的骨干掉队。定期更新，不搞终身制

**最容易被跳过的是"在行动中检验"这一步**——不看结果，整个闭环就断了，你会一直重复自己的偏见。

## A1 — 书中的应用 (Past Application)

### 案例 1：解放战争报告制度（1948）
- **问题**：解放战争打到关键阶段，各地"事前不请示、事后不报告"，中央不知道前线真实情况
- **方法论的使用**：建立信息循环制度——书记亲自写报告（**不能让秘书过滤信息**）→ 中央整理分析 → 形成决策下发 → 各地执行后再反馈
- **结论**：核心不是"收集信息"，而是一个持续闭环：收集→整理→决策→验证→再收集
- **结果**：形成制度化的决策循环

### 案例 2：健身账号做知识付费（商业源迁移例）
- **问题**：3 万粉，想做知识付费但不知道卖什么
- **方法论的使用**：①收集最近 100 条评论和私信统计需求 → ②归类（"怎么减肚子"35 次、"新手计划"28 次、"饮食"20 次）→ ③发视频验证"我准备出 28 天减腹计划，你们需要吗" → ④先做低价试水版收反馈再出完整版
- **结论**：不是做一次调查就结束，而是**每两周重复一轮**
- **结果**：产品基于验证过的真实需求

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill？

1. 不知道粉丝/客户到底想买什么，出了产品没人买
2. 有很多评论和私信但不知道怎么提取有用信息
3. 拍脑袋做了个产品，上架才发现不是用户要的
4. 收集了很多反馈但决策时还是凭感觉
5. 用户说想要 A，你做了 A，结果他们不买单
6. 要定一个会影响别人的规则/方向/产品，怕判断脱离对象

### 语言信号

- "不知道用户真正要什么"
- "怎么获取/用好用户反馈"
- "产品卖不动，问题在哪"
- "他们说要 X，但做了又不买"
- "how do I know what my users really want"

### 与相邻能力的区分

- 与 `mao-research`（调查研究）的区别：调研多是**一次性**的准入判断（这个方向能不能做）；本卡是**持续循环**（每两周一轮）。**还没用户时先做调研，有用户后做闭环。**
- 与路由入口内的"突破一点再推广"的区别：试点针对**自己的方案**（先在点上验证方案本身），群众路线针对**对象的需求**（从对象那里收集→加工→再回到对象）。两者配套：试点是"从群众中来"的动作，推广是"到群众中去"的动作。

## E — 可执行步骤 (Execution)

1. **从群众中来：收集 + 加工**
   - **收集**：不是征求意见，是收集**他们已经在做的事和说过的话**——评论区、私信、后台搜索词、转发附言、一线绕开流程发明的"土办法"
   - **加工**：摊开原始反馈 → 去掉重复和情绪化表达 → 归类（哪些是同一需求的不同说法）→ 排序（频次 × 强度）
   - **关键一步**：找出"他们没说但做了的"——**行为比语言诚实**
   - 完成标准：产出归类结果，不是一堆原始留言

2. **化为系统主张（不是罗列）**
   - 变成一个清晰的、可执行的说法，而不是"大家提了十条意见"
   - 完成标准：能用**一句话**讲清主张（讲不清=还没加工完）

3. **到群众中去：贯彻 + 解释**
   - 讲清楚为什么这么定（不是宣布）；让他们参与细化（不是被动执行）
   - **骨干先行**：先让积极分子理解和接受，他们去带动中间的多数
   - 完成标准：有骨干名单，且他们已理解

4. **在行动中检验（最易跳过，必做）**
   - 定下**可观测的检验指标**和**时间点**，然后真的去看（如：完读率+咨询转化数，3 期之后）
   - 完成标准：有"指标+时间"表，且到期真的看了结果

5. **循环 + 骨干更新**
   - 设定循环节奏（如每两周一轮）
   - 定期更新骨干（新的积极分子顶上，掉队的换下）
   - 完成标准：有固定的循环节奏

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **用户还没有** → 还没粉丝/客户时，先做调研（`mao-research`），不是做反馈循环
- **颠覆性创新** → 有时候用户不知道自己需要什么（iPhone 之前没人说想要触屏手机），此时不能纯靠用户反馈
- **一次性决策** → 用调研

### 作者警告的失败模式

- **拍脑袋决策**："我比用户更懂他们需要什么"——不听用户的
- **用户说什么做什么（尾巴主义）**：变成跟屁虫，丧失专业判断力。**集中不是迎合**——群众的意见是原料，需要研究加工
- **收集了反馈但不看**：有渠道但决策时不用，走过场

### 作者的盲点 / 时代局限

- **样本偏差**：愿意留言、愿意提意见的人，往往不是沉默的大多数。要从**行为数据**里补充
- **"群众"要定义清楚**：是目标读者不是所有读者；是一线执行的人不是所有人。搞错对象收集到的是噪音
- **别用"从群众中来"当逃避决策的借口**：收集完还是要有人拍板，拍板的人负责

### 容易混淆的邻近方法论

- "从群众中来"≠ 民主投票。它是**加工**（研究出系统主张），不是**汇总**（取多数意见）
